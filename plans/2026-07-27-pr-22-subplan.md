## 4. The entry-42 back-import check

Entry 42's design note is binding: **no third AST walk.** The implementation is
behavioral — import each mixin module in a fresh interpreter, before
`pdsfile.pdsfile` is imported, and assert `pdsfile.pdsfile` did not land in
`sys.modules`.

**The obstacle the note does not mention, found by measurement.**
`src/pdsfile/__init__.py` does `from .pds3file import *`, so importing *any*
`pdsfile.*` submodule executes the package `__init__` and pulls `pdsfile.pdsfile`
into `sys.modules`. Measured: the naive probe reports `pdsfile.pdsfile in
sys.modules: True` for all nine private modules, i.e. it would be **red for every
module, always** — a check that can never pass is as useless as one that can
never fail.

The fix keeps the check behavioral. The probe installs a **stub `pdsfile` package
module** in `sys.modules` — a real `ModuleSpec` with
`submodule_search_locations` pointing at the package directory, and no
`__init__.py` execution — and then imports the mixin module by name. Relative
imports (`from ._path_utils import …`) and absolute in-package imports
(`from pdsfile import pdscache`) both resolve normally through
`submodule_search_locations`; only the package `__init__`'s star-imports are
excluded. That isolates exactly the property the preamble cares about: *loading
this mixin module must not require `pdsfile.pdsfile`.*

**Shape: one subprocess per mixin module.** A single interpreter importing all of
them in sequence would let module A's import of `pdsfile.pdsfile` mask module
B's, and would let module A's import of B mask B's own violation. One process per
module cannot do either. The modules are discovered from `PdsFile.__bases__` in
the parent process (which may import `pdsfile.pdsfile` freely), so the check
picks up any future mixin for free, the way
`tests/api/test_mixin_collisions.py` does.

**Where it lives:** a new sibling file, `tests/api/test_mixin_import_isolation.py`.
Not `test_api_freeze.py` (§6.4 absolute). Not inside `test_mixin_collisions.py`
either, deliberately: entry 53's owner clause is "whichever Phase-5 PR next edits
the mixin harness", and this PR is directed not to take entry 53 up, so it edits
no existing test file. `tests/api/conftest.py` marks the whole directory
`holdings_free`, which is verified by running the no-holdings job and finding the
new ids in its set — not assumed.

**Proof it can fail** (both halves of the check, both recorded in the PR):

1. A module-level `from pdsfile.pdsfile import repair_case` at the **head** of
   `_associations.py` — a name already bound in core, the spelling entry 42 calls
   *silent*. It imports cleanly in normal order (measured) and the check goes red.
2. The same import at the **tail** of `_associations.py`. This one raises nothing
   anywhere — the probe subprocess exits 0 — and is caught **only** by the
   `sys.modules` assertion. This is the case that proves the assertion, and not
   merely the subprocess exit code, is load-bearing.

Both mutations are made on a scratch copy of `src/pdsfile/` and on the real tree
(reverted), never committed.

## 7. As executed — the delta from this plan

Written after the work. Eight things diverged; each is recorded because the
divergence is the useful part.

1. **The commit sequence gained a commit and swapped two.** This sub-plan is its
   own `docs:` commit ahead of the move, and the entry-42 check now lands
   **before** the module docstring, not after: the docstring names
   `tests/api/test_mixin_import_isolation.py` as one of the two files that enforce
   the mixin mechanics, and a docstring that names a file which does not yet exist
   is false at the commit that introduces it. Final order: sub-plan, move,
   `# Version ranks` banner, dead code, the check, the docstring, the records.

2. **The move commit's byte proof is over two line ranges, not one.**
   `LATEST_VERSION_RANKS` sits in the middle of the block at line 2036, so the
   moved text is `672–2034` + `2037–2230`. Dropping line 2035 (the blank *before*
   the class attribute) rather than 2037 is what leaves exactly one blank line at
   the join; picking the other one would have left two.

3. **The dead-code detector needed two passes, and the AST pass alone was short by
   three.** It groups maximal runs of consecutive comment lines, and three of the
   eight lines sit directly beneath a line of prose, so the run fails to parse and
   is discarded whole. §7 of the validation record says which three and why. A
   single-pass inventory would have shipped a list missing 3 of 8 — on a
   deliverable whose entire content *is* the list.

4. **The first draft of `_PropertiesMixin`'s docstring had five errors, all caught
   by running the derivation rather than by reading.** It called
   `all_version_abspaths` a non-property (it is one; the non-properties are four,
   not five); it said fifteen sibling-mixin methods where the widened walk finds
   seventeen, the two extra being `pdsfiles_for_basenames` and
   `viewable_childnames_by_anchor`, reached through `parent` rather than `self`;
   it claimed `_all_version_abspaths` is read but never written, when
   `all_versions` writes it onto each sibling PdsFile; it named two of the three
   methods that read `IDX_EXT`; and it listed `re` and `pdstable` as out-of-scope
   module methods although the block references neither. This is exactly the
   defect class the briefs predict — a figure or phrase stated rather than
   measured — and it is recorded rather than quietly fixed.

5. **`_properties.py`'s first import block was an I001 gain, caught before the
   commit.** The per-code conservation table showed I001 at parent 1, head 1,
   `_properties.py` 1 — a sum of 2 against a parent of 1, which is a ratchet
   *widen*. The fix was to write the header the way ruff's isort wants
   (`pdsparser` before `PIL`, two blank lines before the banner) so it reports
   zero and needs no I001 entry. §5's "the codes move with the code" is only true
   if the *new* lines a move commit adds trigger nothing new.

6. **One monkeypatch forced-wrong control needed a different form**, and the first
   attempt is recorded as deferred observation 61. Removing the `glob` stub in
   `test_pdsfile_path_resolution.py` leaves everything green on Linux, because the
   stub suppresses a MacOS-only path rather than supplying a value; forcing it to
   answer wrongly is the control that works. The "delete the patch, watch it go
   red" recipe PR-17 through PR-21 used is sound only for patches of the first
   kind.

7. **There are ten private modules, not nine.** §4 of this plan and the common
   brief both say "nine", counting mixins; `_path_utils.py` is a tenth private
   module with its own ratchet entry and its own dead-code line, and the
   conservation check in §9 of the record covers all ten. The union of the ten
   entries is 15 codes, every one of which is in `rewrite`'s `pdsfile.py` entry.

8. **`pdsfile.py` lands at 1,935 lines, not ~1,750.** Decomposed in §19 of the
   record: +82 because the commented-out code is eight lines rather than ~89, +74
   for the module docstring the same plan section asks for, +41 because PR-16–21
   removed 2,889 lines net rather than ~2,930, +6 for the banner. Nothing on the
   stay-list was extracted to close the gap, which is what the target is a check
   on.
