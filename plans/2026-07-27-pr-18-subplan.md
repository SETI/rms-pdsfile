**Branch:** `pr-18-derived-paths`, based on `pr-17-shelves-local-fs` @ `ca7a43d`

`plans/2026-07-27-addendum-phase5-stack-extension.md`)
**Scope:** one new private mixin module, the import and base that build `PdsFile`
from it, and the plan-mandated deduplication of the three `log_path_for_*`

PR-18 is marked **(M)**, so §6.4 step 1 does not require a sub-plan. This one
exists because the PR carries **two distinct kinds of change** — a pure move and a
content edit — which §2's commit-granularity rule forbids interleaving, and
deciding the commit sequence before writing any code is exactly what a sub-plan is
for. `plans/2026-07-27-pr-17-subplan.md` is the model, including the "as executed"
delta appended at the end rather than editing the plan after the fact.

## 1. What moves

Eleven methods, located **by symbol**. The parent plan's ":4898–5059" and
":5361–5516" windows are against the 6,304-line original; PR-15, PR-16 and PR-17
have all edited this file and it is 5,436 lines at the parent tip. On that tip the
targets are three consecutive banner blocks:

| Banner | Definitions |
|---|---|
| `# Checksum path associations` | `checksum_path_and_lskip`, `checksum_path_if_exact`, `dirpath_and_prefix_for_checksum` |
| `# Archive path associations` | `archive_path_and_lskip`, `archive_path_if_exact`, `dirpath_and_prefix_for_archive`, `archive_logpath` |
| `# Log path associations` | `set_log_root` (a classmethod), `log_path_for_bundle`, `log_path_for_bundleset`, `log_path_for_index` |

They all become methods of **`class _DerivedPathsMixin`** in
**`src/pdsfile/_derived_paths.py`**.

### 1.1 The one mechanical subtlety: the move steps around a block it must not touch

The checksum/archive window and the log window are **not contiguous**. Between
them sits the `# Shelf support` banner, holding the six class attributes PR-17
deliberately left on `PdsFile`:

```
    SHELF_CACHE, SHELF_ACCESS, SHELF_CACHE_SIZE,
    SHELF_CACHE_SLOP, SHELF_ACCESS_COUNT, SHELF_NULL_KEY_VALUES
```

**Neither the attributes nor the banner is touched.** The extraction is therefore
two deletions from `pdsfile.py`, not one.

### 1.2 `LOG_ROOT_` does not move

`LOG_ROOT_ = None` opens the log-path banner block and is a **class attribute**,
so the Phase-5 preamble keeps it on `PdsFile` — the same rule that kept the six
shelf attributes there. It is also a **frozen manifest member**
(`tests/api/api_manifest.json`, `PdsFile.LOG_ROOT_`, `"kind": "data"`), which makes
the answer not merely conventional: moving it off the class would be a manifest
break.

Both halves of its traffic keep working from a mixin, because both go through the
class at call time: `set_log_root` is a classmethod that assigns `cls.LOG_ROOT_`,
and the three `log_path_for_*` methods read `cls.LOG_ROOT_` after
`cls = type(self)`. `LOGFILE_TIME_FMT` (also frozen, also a class attribute, read
as `cls.LOGFILE_TIME_FMT`) stays for the same reason and is not in the move list.

The `# Log path associations` banner therefore stays in `pdsfile.py` too, with
`LOG_ROOT_` under it — exactly the shape PR-17 left the shelf block in.

## 2. The sweep, done mechanically — and in both directions

**Direction 1 — what must move with the code.** The PR-16/PR-17 two-pass method:
CPython's `symtable` for the module-global names each moved definition's *body*
references, plus an AST pass over each definition's *decorator expressions and
argument defaults*, which are evaluated in module scope and which `symtable` does
not attribute to the method. The second pass is not optional — it is what caught
PR-16's `_GLOB_CACHE_SIZE` and PR-17's `PATH_EXISTS_CACHE_SIZE`, both referenced
only inside an `@functools.lru_cache(maxsize=…)` argument.

The full output, including its "nothing else" lines, goes in the validation record.

**Direction 2 — who *patches* what this PR moves** (deferred entry 29, owned by
"PR-17 onward"). The free-variable sweep cannot see a test that patches a name on
a module the code no longer resolves through; such a test keeps passing while
testing nothing, and §6.2's outcome-set diff is *structurally blind* to it. Steps,
unchanged from PR-17 §2:

1. grep all of `tests/` and `scripts/` for `monkeypatch.setattr`/`setitem`/
   `delattr`/`setenv`/`delenv`, `mock.patch`, `patch(`, `patch.object`,
   `setattr(`, and direct module- or class-attribute assignment;
2. enumerate every site whose target names `pdsfile.pdsfile` or any symbol this PR
   moves, and classify each as still-reaching or broken;
3. for every such site, **prove the test still goes red when the patched behavior
   is wrong** — force the patched call to answer wrongly and confirm the failure;
4. this PR's own extra: the log paths embed a **timestamp**. Find out whether
   anything pins the clock, and if so whether the pin still reaches the moved
   code. A test that silently stops pinning the clock passes today and fails at
   midnight on someone else's machine.

## 4. The deduplication — the one content change

The parent plan: "Deduplicate the three near-identical `log_path_for_*` bodies
into one private `_log_path_for(...)` helper the three methods delegate to
(behavior-identical, golden-tested via the tool tests from PR-13)."

**The helper is a private method on the mixin**, not a module-level function. It
needs `self` for six attribute reads and `type(self)` for `LOG_ROOT_` and
`LOGFILE_TIME_FMT`; as a module-level function every one of those becomes an
explicit argument or an explicit `pdsf.` prefix, which is more code and reads
worse. As a method the lookups are unchanged from today's. It is underscore-
prefixed, so it is freeze-invisible, and it introduces **no new state**.

**The three bodies are *near*-identical, so the divergences are the whole risk.**
They are enumerated before the helper is written, from a three-way diff of the
three bodies, and each one is reproduced by a parameter rather than collapsed:

| # | Divergence | How the helper reproduces it |
|---|---|---|
| 1 | default `dir`: `''`, `''`, `'index'` | the **public** signatures are frozen and are not touched; the default is applied before delegation |
| 2 | `log_path_for_index` has **no `suffix` parameter** and no suffix block | it passes `suffix=''`, and `if suffix:` is then false — the same instructions execute |
| 3 | `log_path_for_index` first raises `ValueError('Not an index file: …')` when `not self.is_index` | the check **stays in the public method, before the delegation**, so it still precedes the `place` validation |
| 4 | the parts naming the target: `[category_, bundleset_, bundlename]` / `[category_, bundleset, suffix]` / `[logical_path.rpartition('.')[0]]` | passed in as the helper's first argument |
| 5 | everything else — the `place` branch, the log-root branch, the `dir` branch, the time tag, the task tag, `'.log'`, the `''.join` | identical in all three today, and is the body of the helper |

Two consequences to check rather than assume:

- **Evaluation order.** Building the target parts in the caller moves those
  attribute reads *before* the `place` validation. All six names — `category_`,
  `bundleset_`, `bundlename`, `bundleset`, `suffix`, `logical_path` — are plain
  instance attributes assigned in `PdsFile.__init__`; reading one cannot raise and
  has no side effect, and `str.rpartition` is pure. This is verified mechanically
  against `PdsFile` and every registered subclass (no data descriptor of that name
  on the type), not asserted. The one genuinely lazy read — the `is_index`
  property, which can call `self._recache()` — is divergence 3 and is deliberately
  left where it is.
- **`archive_logpath` is a caller of the deduplicated surface** (`this.copy()`,
  then `log_path_for_bundle('_targz', task=task, dir='archives')`), so it is a
  free correctness check on the helper. It is exercised by
  `tests/pds3file/test_pds3file_blackbox.py::test_archive_logpath`.

**`dir` is a frozen parameter name.** It shadows a builtin — that is why `A002`
is in `pdsfile.py`'s ratchet entry and why the plan's PR-23 section lists it as a
permanent freeze-locked ignore. The three public parameters stay named `dir`; the
helper's own parameter is named **`subdir`**, so the helper adds no `A002` of its
own. `A002` moves to `_derived_paths.py` as a split either way, and §5 measures it.

**Golden coverage.** The regression net for this edit is
`tests/pds3file/test_pds3file_blackbox.py`: 16 parametrized cases for
`log_path_for_volume` (→ `log_path_for_bundle`), 16 for `log_path_for_volset`
(→ `log_path_for_bundleset`), 8 for `log_path_for_index` and 1 for
`archive_logpath`, each covering both `place` values, with and without `suffix`,
`task`, `dir` and an explicit log root. Which of PR-13's
`tests/holdings_maintenance/` tool tests additionally reach these methods is
**measured** from the recorded run's coverage data, not guessed, and the answer
goes in the PR whichever way it comes out. It is information, not a licence to add
scope: the gate remains an identical pass/fail set.

## 5. Ruff ratchet

`per-file-ignores` may only shrink. Same per-code procedure PR-16 and PR-17
recorded, with the two flags their records flag as traps (`--isolated` drops
`line-length = 100`, and ruff 0.15's default output format no longer starts a line
with the file path):

```
ruff check --no-cache --isolated --output-format concise --select <code> \
           --line-length 100 --target-version py310 <file>
```

1. For every code in `pdsfile.py`'s entry, run the above against `pdsfile.py` and
   `_derived_paths.py` after the move.
2. `_derived_paths.py` gets an entry listing **exactly** the codes its moved lines
   still trigger, with the same explanatory comment the other moved-module entries
   carry. Every such code must already be in `pdsfile.py`'s entry — the entries are
   a **split**, not a new suppression. **A code that is not already there is a
   §6.4 hard stop.**
3. Any code `pdsfile.py` no longer triggers is **removed** from its entry.
4. Net effect recorded as a before/after per-code count, at the extraction commit
   and again after the dedup commit. The dedup may legitimately *shrink* the
   ratchet — three copies of a violation becoming one, or vanishing. Shrinking is
   allowed and welcome; growing is a hard stop.

Moved bodies are not restyled to shed an inherited violation at the extraction
commit — that is a content edit inside a move, and it belongs to PR-23.

## 6. Keeping `pdsfile.pdsfile.X` resolving

The measured invariant is `sorted(vars(pdsfile.pdsfile))`: **no name lost**.

The sweep names exactly one module-level import the moved code needs —
`datetime` — and `pdsfile.py` still uses `datetime` in seven places in the
properties block, so its import stays a plain `import datetime` and no
redundant-alias re-export is needed. **No module-level name moves out of
`pdsfile.py` in this PR**, which is the difference from PR-16 and PR-17; that is
verified, not assumed.

One name is **added** to `pdsfile.py`'s namespace: `_DerivedPathsMixin`, which the
`class PdsFile` statement needs. It is an underscore name, so the manifest does not
see it.

## 7. Base order

`_DerivedPathsMixin` sorts before `_LocalFsMixin`, so the class statement becomes

```python
class PdsFile(_DerivedPathsMixin, _LocalFsMixin, _ShelfMixin, object):
```

The rule is **alphabetical by mixin class name, with `object` last**, recorded and
owner-acknowledged in `plans/2026-07-27-addendum-phase5-mixin-base-order.md` and
enforced by
`tests/api/test_mixin_collisions.py::test_the_mixin_bases_are_listed_alphabetically`.
The Phase-5 preamble's illustration on this branch shows the opposite order; it is
corrected in PR #110, which merged to `rewrite` after this stack branched, so the
addendum is the authority here. That test file **discovers** the mixins from
`PdsFile.__bases__`, so this PR's mixin inherits all of its checks — collision,
shadowing, reachability, no-`__init__`, callables-and-properties-only and base
order — for free, and adds no test id. Run it first, before anything else.

## 9. Which half of issue #47 this is

The parent plan is explicit and the PR description must be too:

- **This PR does the file-location half.** `set_log_root` and the three
  `log_path_for_*` methods — used only by the maintenance tools — move physically
  out of `pdsfile.py`.
- **Because of the API freeze they stay reachable as `PdsFile.set_log_root` and
  `PdsFile.log_path_for_*`**, and the tools keep calling them exactly as today.
  The move is invisible to callers.
- **Removing them from the public class surface — what #47 ultimately wants — is
  an API break deferred to phase "b".** It is not done here, not half-done here,
  and **issue #47 stays open.**

## 10. Hard stops for this PR

Any manifest diff at all; **any** pass/fail set movement in either mode (this PR
adds no test id, so there is no legitimate movement); a ruff code needed by
`_derived_paths.py` that is not already in `pdsfile.py`'s entry; a moved body that
cannot be kept byte-identical at the extraction commit; a divergence between the
three `log_path_for_*` bodies that the helper cannot reproduce by parameter; a
monkeypatch site that cannot be made to fail on wrong behavior.
