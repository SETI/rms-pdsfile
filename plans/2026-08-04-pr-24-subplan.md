## 3. Classification rule

Every violation is either **fixed** or **permanently excluded**. The rule, stated
before the table so it can be checked against it, is PR-23's:

**Fix** a violation only when the rewrite is provably behavior-identical **from
evidence local to the same function, or from an exhaustive enumeration of the
assignments to the name involved**.

**Exclude** it permanently when any of:
- **(a)** the fix changes a frozen public name, signature or manifest member;
- **(b)** the only fix is a `ClassVar` annotation — ground rule 5;
- **(c)** the fix requires rewriting a hand-aligned block — the same objection
  that got `ruff format` dropped on 2026-08-03;
- **(d)** equivalence cannot be established locally and rests on a whole-program
  argument, or on the behavior of a third-party callee;
- **(e)** the fix changes the value, the type, the emitted text or the exception
  raised on any path — including log text and frozen sidecar output, which §2
  names as observable;
- **(f)** the fix is a code change beyond a style PR's warrant whose scope the
  owner has not settled;
- **(g)** the file may not be edited at all (§6.4 prohibition);
- **(h)** a ground rule or an overrides deviation freezes the file itself, so no
  violation in it is this PR's to fix.

## 4. The two rules this PR is asked to state

### 4.1 The logging-call rule (§6a of the brief, deferred entry 79)

`UP031`'s ruff fix is an f-string, and the owner's logging rule forbids f-strings
in logging calls: a logging call passes a `%`-style format string and the values
as *arguments*. The lazy conversion is **not** mechanical here, because
`pdslogger.PdsLogger.log` (venv `pdslogger/__init__.py:1484`, and `.open()` at
`:1236`) resolves a lone positional argument as the keyword-only `filepath` when
the message contains no `%` pattern. So

```python
logger.info('Label found for %s' % abspath, label_abspath)   # today
logger.info('Label found for %s', abspath, label_abspath)    # TypeError
logger.info('Label found for %s', abspath, filepath=label_abspath)   # correct
```

An AST sweep of `src/pdsfile/` measured **132** logging calls that build their
message eagerly, **69** of which also pass a positional filepath argument and so
would break under the naive rewrite. (Deferred entry 79 and the coordinator's
scoping both say 130/67; both used a `LOG_METHODS` set missing `pdslogger`'s
`normal()`, which adds `pds4checksums.py:119` and `:128`. The corrected figures
and the method-set omission behind them are recorded as **deferred observation
82**.)

**The rule, applied to all 144 `UP031` sites:**

> `UP031` is converted to an f-string only where the site is an **exception
> message** or a **`print()`** — the two places where an f-string is
> unambiguously this project's style and nothing observable depends on the
> `%` spelling. It is **permanently excluded** on (i) logging calls, (ii)
> `file.write()` calls that emit the frozen sidecar formats, and (iii) any `%`
> that sits in a hand-aligned column block.

Which gives **5 fixed** (3 exception messages in `COUVIS_0xxx.py`, 2 `print()`s
in `shelf_consistency_check.py`) and **139 excluded** (46 logging, 24
`file.write`, and 69 more: 51 in hand-aligned blocks, 12 plain `%` expressions
that the positive rule simply does not reach, and 6 in `re_validate.py`, which is
frozen outright). Converting the logging calls is a
code change beyond a `ruff check` PR's warrant — entry 79 says so in terms — and
the owner has not scoped it; rule (f).

`pdsviewable.py:529` shows the filepath bug already live in the tree. It is
PR-23's file and entry 79 owns it; it is **not** touched here.

### Three things the mechanical fixes got wrong, and how they were caught

These are the reason a style PR is not a `--fix` run.

1. **`C405`'s autofix silently misaligned every multi-line set literal.**
   `set([` is five characters and `{` is one, and ruff rewrites the opening
   delimiter without re-indenting the continuation lines, so each one ended up
   four columns off the opening brace — the same hand-alignment damage that got
   `ruff format` dropped. All twelve multi-line sites were re-indented by hand.
   The first attempt at that re-indent over-reached and dedented four set
   literals in `pds4infoshelf.py` and `pds4linkshelf.py` that were **already**
   `{…}` and had no `C405`; those four were restored and verified byte-identical
   to `origin/rewrite`. What caught both is a `git diff` vs `git diff -w`
   line-count comparison per file: every whitespace-only changed line is now
   accounted for as either a `C405` continuation or the `SIM102` dedent.
2. **One `F841` fix introduced a `B018` that the baseline did not have.**
   Dropping the binding from `res1 = target_pdsfile.data_set_id` leaves a bare
   attribute access, which ruff then reports as a useless expression — a code
   appearing after that was absent before, i.e. a widen. Rewritten as
   `_ = target_pdsfile.data_set_id`, the form PR-23 used for the same situation.
3. **`F841` on `pdsarchives.py`'s `proceed` removed six bindings, not one.**
   ruff reports the variable once and its fix drops every assignment to it. That
   is correct here — all five task calls are retained as expression statements
   and nothing reads `proceed` — but it was checked against the sibling tools
   first, because `pdschecksums.py:915` gates a chained step on the same
   variable. `pdsarchives` has no such step. Recorded as deferred observation 83.
