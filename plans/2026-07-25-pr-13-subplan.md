# PR-13 sub-plan — maintenance-tool test suite (issue #82)

**Date:** 2026-07-25
**Parent plan:** `plans/2026-07-25-modernization-plan.md` §5 Phase 3, PR-13 (size L)
**Branch:** `pr-13-maintenance-tool-tests`, based on `rewrite` @ 8d5cf16
**Scope:** tests only. No `src/pdsfile/` change of any kind.

Written per §6.4 step 1 (PRs marked L get a short sub-plan first). It records the
choices the parent plan left to the executor, the two places where reality
differs from a premise the parent plan states, and the order of work.

## 1. Subjects (the "designated small volume/bundle")

The parent plan requires the smallest suitable volume/bundle that has both a
data tree and metadata present, verified against the goldens' reference root
(the limited testing copy).

| Flavor | Subject | Source files | Size |
|---|---|---|---|
| PDS3 | `HSTNx_xxxx/HSTN0_7176` | 6 under `volumes/`, 4 under `metadata/`, 1 under `_volinfo/` | ~1.1 MB |
| PDS4 | `uranus_occs_earthbased/uranus_occ_u0_kao_91cm` | 6 under `bundles/`, 3 under `metadata/` | ~0.5 MB |

Both are far inside the "~50 files / ~50 MB per module" budget. Rationale:

- **PDS3 `HSTN0_7176`** is the smallest volume in the reference root that has a
  real PDS3 detached label with internal links (`N4BI01L4Q.LBL` points at five
  siblings), viewable products (JPG/TIF, so the info shelf records image
  dimensions), *and* a metadata directory with two labelled index tables
  (`*_index.tab`, `*_hstfiles.tab`) that `pdsindexshelf` can shelve. Smaller
  candidates (`COISS_3xxx/COISS_3002`, `RPX_xxxx/RPX_0001`,
  `RES_xxxx_prelim/RES_0001`) have no label-to-data links, no metadata, or
  content that differs between the two roots. The volume-set description under
  `_volinfo/` is declared too, because `Pds3File.preload()` reads it and
  `show_opus_products` preloads.
- **PDS4 `uranus_occ_u0_kao_91cm`**, three matched label/table pairs from one
  collection plus the bundle's three metadata index tables. The pairs are the
  point: a PDS4 label links to its data file by name, so a subset of labels alone
  would shelve an empty link graph and the `pds4linkshelf` tests would assert
  nothing. `uranus_occ_u0201_palomar_508cm` is smaller and was the first choice,
  but the reference root holds only its labels, not its tables; the other PDS4
  bundle set (`cassini_uvis_solarocc_beckerjarmak2023`) is a single 212 MB bundle,
  an order of magnitude over budget.

## 2. Two corrections to premises in the parent plan

Both were measured, not assumed. Neither changes a PR-13 deliverable; both are
recorded here so the deviation is visible and so the design compensates.

### 2.1 The limited testing copy is **not** byte-identical to the complete set

The parent plan says the copied subset is "identical across machines because the
limited copy is a copy of the complete set". That is false in general: in the
reference root, **35,425 of 49,480 files under `volumes/` are zero-byte
placeholders** (the metadata, and the whole PDS4 tree, are essentially intact).
A subset chosen without care would therefore produce *different* checksums,
sizes and shelf contents depending on which root the test ran against, and the
committed goldens could only ever match one of them.

Compensation, entirely within the spec's shape:

- Both subjects above were chosen so that **every declared source file is
  byte-identical in both roots** (verified file-by-file by md5).
- The per-module source table pins not just the mtime but also the **size and
  md5 of each declared source file**. The module-scoped fixture treats a missing
  path *or* a content mismatch identically: **skip the module** (with the
  existing `full_holdings` marker). This turns the parent plan's *assumption*
  that source bytes are stable into an *enforced precondition*, and makes a
  future truncated/renewed holdings copy produce a clean skip rather than a
  mystifying golden diff.

### 2.2 Tools must be driven as subprocesses, not by calling `main()` in-process

The parent plan mandates subprocess invocation only for `shelf_consistency_check`
and `show_opus_products` (because they have no `main()` yet). For the other
tools it is silent. **All tool invocations in PR-13 use subprocesses**, because
in-process invocation is not merely inconvenient, it is wrong:

`PdsFile.CACHE` is a **class-level** cache keyed by *logical* path (looked up at
the top of `from_abspath`), and `tests/conftest.py` preloads the real holdings once
per session, permanently caching every category, bundle-set and bundle directory.
A same-process
`Pds3File.from_abspath('<tmp_path>/holdings/volumes/HSTNx_xxxx/HSTN0_7176')`
resolves to logical path `volumes/HSTNx_xxxx/HSTN0_7176`, hits that cache, and
returns a `PdsFile` whose `abspath` points at the **real holdings tree** — so a
`--repair` or `--reinit` test could write into real holdings. A subprocess with
`PDS3_HOLDINGS_DIR`/`PDS4_HOLDINGS_DIR` pointed at the copied tree has an empty
cache and no preload, and cannot reach the real tree.

Subprocess invocation is also what the frozen surface actually is: the Phase 6
consolidation must not change CLI flags, output, log format or exit codes, and
these tests assert exactly those. PR-28 will still convert the two `main()`-less
tools to in-process calls as the parent plan says; that is orthogonal.

Two consequences the tests handle explicitly:

- The subprocess environment pins **`TZ=UTC`**. Info-shelf sidecars format
  mtimes with `datetime.fromtimestamp(...).strftime(...)` — local time. Pinned
  mtimes alone are not enough to make a golden portable; the timezone must be
  pinned too.
- The subprocess environment **removes `PDS_LOG_ROOT`**, so the tools fall back to
  the `logs/` directory beside the holdings root — which, for a temporary tree, is
  inside `tmp_path`. No test writes a log outside it.

## 3. Pre-existing tool defects that the tests pin rather than fix

PR-13 is behavior-preserving; per §6.4 a fix here would be a hard stop. Where the
mandated `--init → --validate` cycle cannot be green today, the test **pins the
current (broken) behavior** and says so in its docstring, so the PR that fixes it
sees a failing pin. Each is also appended to
`critiques/deferred-observations.md`.

Five defects and two further observations were found. They are written up in full
— source location, symptom, pinning test, and owning PR — as the numbered entries
under "From PR-13" in `critiques/deferred-observations.md`, and the test
docstrings point there rather than repeating them:

1. `pds4archives` cannot round-trip: `--validate` fails immediately after a
   successful `--initialize` because members are written and read back with
   different prefixes. → PR-25.
2. `pds4archives` on a *bundle* (rather than a bundle set) dies on a bare
   `raise`. → PR-25.
3. `pds4indexshelf` cannot shelve either available PDS4 dataset: it reads tables
   through a PDS3 detached-label reader. → PR-27.
4. `pds4linkshelf --update` raises `AttributeError` against any existing shelf;
   its pds3 twin merges the same data correctly. → PR-27.
5. `pdschecksums` and `pds4checksums` never propagate logged errors into the exit
   code. → PR-25 (its shared `run_main()` changes this by design; the pins must be
   updated with it).

Plus: `shelf_consistency_check` targets a legacy `shelves/` layout that current
holdings no longer use (→ PR-28), and info-shelf sidecars are local-time
dependent, which is why the tests pin `TZ=UTC` (→ Phase 6).

## 4. Layout

```

├── __init__.py
├── conftest.py                 # tool-tree fixtures + subprocess runner
├── subsets.py                  # the explicit source tables (paths+mtime+size+md5)
├── support.py                  # copy/pin/verify, golden compare, parsers
├── test_crlf.py                # holdings-free
├── test_task_flags.py          # argparse two-flag pinning (for PR-25)
├── test_pds3_checksums.py      test_pds4_checksums.py
├── test_pds3_archives.py       test_pds4_archives.py
├── test_pds3_infoshelf.py      test_pds4_infoshelf.py
├── test_pds3_linkshelf.py      test_pds4_linkshelf.py
├── test_pds3_indexshelf.py     test_pds4_indexshelf.py
├── test_pds3_dependency.py     # pds3-only tool
├── test_shelf_consistency_check.py
└── test_show_opus_products.py
tests/golden/full/holdings_maintenance/*.txt   # small text goldens (<1 MB total)
```

`SOURCE_PATHS` and `SOURCE_MTIMES` are declared **at module level in every test
module**, as the parent plan requires, and are built from the explicit literal
tables in `subsets.py` (each module names the subset it needs; index-shelf
modules take only the metadata slice). The tables live in one file rather than
being copy-pasted twelve times so that a single audited list of source files is
reviewable and cannot drift between modules.

The tree is module-scoped, as the parent plan requires, but rebuilding it from the
locally staged sources is cheap, so **every test rebuilds it first**: each test is
independent and order-agnostic, single test ids can be rerun, and the suite is
safe under `pytest -n`.

## 5. Test shape per tool pair

Module-scoped `tool_tree` fixture → verify sources → copy into `tmp_path` →
`os.utime` from `SOURCE_MTIMES`. Then, over that one tree, in order:

1. `--initialize` from scratch; assert exit 0.
2. Compare the produced artifact against the committed golden — **normalized**,
   never raw bytes: md5 files as a sorted `{path: md5}` mapping (the tool writes
   them in `os.walk` order), `.py` sidecars as normalized text, archives as sorted
   `(name, kind, size, mtime)` **member tuples** (directory mtimes reported as 0,
   since only file mtimes are pinned).
3. `--validate`; assert exit 0 and no `ERROR` lines.
4. Apply one fixed corruption from the module's `CORRUPTIONS` table (never
   randomized); `--validate`; assert non-zero exit **and** the specific log text.
5. `--repair`; assert exit 0; `--validate` clean again.
6. Add one new file; `--update`; assert the artifact now covers it.

For the three defects in §3 the corresponding step asserts the current failure
mode instead, with a docstring naming the PR that owns the fix.

## 5a. Deviations from the active plan

PR-13 departs from the letter of the active plan in two places, both forced by
PR-13's own stated deliverables. They are written up for owner acknowledgement in
`plans/2026-07-25-addendum-holdings-free-marker.md`, as `plans/README.md` and §6.4
require:

1. **`tests/conftest.py`'s collect-and-skip rule is modified** so that tests marked
   with a new `holdings_free` marker still run when no holdings are available.
   §5 of the plan says PR-09's machinery is untouched, but the PR-13 section
   requires the `crlf` tests to "run everywhere", which PR-09's unconditional skip
   made impossible. What ground rule 3 enumerates as the retained plumbing — the
   flavor resolver, the env vars, `full_holdings`, `tests/golden/full/` — is not
   touched, and the mini flavor stays dormant. With no holdings env vars set the
   suite goes from 713 skipped / 0 passed to 794 skipped / 23 passed.
2. **`tests/holdings_maintenance/` is added to one suite invocation, not both.**
   The tools run in subprocesses, so `--mode` cannot reach them and the
   shelves-only pass would repeat identical work at double the cost.

## 6. Out of scope (recorded, per ground rule 7)

`re_validate.py` and the `*.sh` sync scripts are not tested and not imported.
`test_import_safety.py` is **not** added; instead the exclusion is documented in
`tests/holdings_maintenance/__init__.py` and in the PR description, because
importing `re_validate` at collection time is exactly what ground rule 7 says to
leave alone.

## 7. Order of work

1. Record the pre-change baseline (`--mode ns` 679P/34S, `--mode s` 555P/3S) as a
   per-test set. **Done before any edit.**
2. `subsets.py`, `support.py`, `conftest.py`.
3. `test_crlf.py`, `test_task_flags.py` (holdings-free / cheap).
4. PDS3 modules, then PDS4 modules; generate goldens via `--update`.
5. `test_shelf_consistency_check.py`, `test_show_opus_products.py`.
6. Add `tests/holdings_maintenance/` to the not-shelves-only invocation in
   `scripts/automated_tests/pdsfile_main_test.sh`. Not the shelves-only one: the
   tools run in subprocesses, so `--mode` cannot reach them and a second run would
   cost time for no signal.
7. Gates: `ruff check`, API-freeze, clean-install, both suite modes against the
   reference root **and** the complete set, per-test pass/fail set diffed against
   the baseline.
8. §6.6 adversarial review loop to convergence; records in `critiques/pr-13/`.
