## Diagram verification method

Each diagram edge and label is checked against a named `file:line` before the
diagram is committed (kept in working notes, not in the page). After the build,
`docs/_build/html/dev_guide/dev_guide_architecture.html` is opened and checked
for: five `<pre class="mermaid">` blocks, the mermaid script tag, and the
diagram sources surviving intact. Mermaid syntax is validated by rendering the
five sources with mermaid locally if available, otherwise by strict eyeball
against the Mermaid grammar plus the reviewer rounds; the Sphinx build does not
parse mermaid text, so a syntax error there would publish a dead block — that is
exactly the class of defect the round briefs will name.

Cross-reference rules: every API symbol in prose gets a role; no dependence on
the five `LinkInfo` attribute targets (observation 1001) or on unpublished
docstrings (deferred 333). No roles inside diagram blocks, code blocks or
literal blocks. No nested markup inside bold (`tests/docs/test_markup.py` gates
it).
