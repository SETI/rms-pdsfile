## 3. Classification rule

Every violation is either **fixed** or **freeze-locked**. The plan's three
freeze-lock reasons are "changes a frozen public signature/name", "needs an inline
type annotation (ground rule 5)", and "requires reformatting an aligned table",
and it says to expect others. The rule used here, stated before the table so that
it can be checked against the table:

**Fix** a violation only when the rewrite is provably behavior-identical **from
evidence local to the same function, or from an exhaustive enumeration of the
assignments to the name involved**.

**Freeze-lock** it when any of:
- **(a)** the fix changes a frozen public name, signature or manifest member;
- **(b)** the only fix is a `ClassVar` annotation — ground rule 5;
- **(c)** the fix requires the multi-line-import / aligned-block reflow the owner
  dropped on 2026-08-03;
- **(d)** equivalence cannot be established locally and rests on a whole-program
  reachability argument about a runtime type;
- **(e)** the fix changes the value, the type, or the exception raised on an edge
  or error path — including log text and traceback content, which §2 names as
  observable.

## 4. The behavior-affecting codes, and how each is discharged

"Mechanical" describes the diff, not the risk. §2 permits exactly three PRs to
change observable behavior and this is not one of them.

- **`E721` (3)** — the fix is **`is` / `is not`, never `isinstance`**.
  `isinstance` accepts subclasses, and all three sites are in a package built on a
  subclass hierarchy: `pdsfile.py:748` is `elif type(self) == PdsFile` inside
  `__repr__`, where `isinstance` would change the repr of every `Pds3File` and
  `Pds4File`; `pdsviewable.py:568` is `type(pdsfiles) != list`, where `isinstance`
  would stop wrapping a list subclass. `type(x) is C` differs from `type(x) == C`
  only if the metaclass of `type(x)` overrides `__eq__`; every class here has
  metaclass `type`.
- **`F841` (9)** — removing a binding is safe only if the right-hand side has no
  effect. Two sites' right-hand sides **do**: `_preload.py:199` and
  `pdsfile.py:1113` are cache subscripts. Both keep the subscript as an expression
  statement; only the `STORE_FAST` goes.
- **`B904` (4)** — **all four freeze-locked**. Both available fixes change
  observable state: `from err` sets `__cause__` and `__suppress_context__` (the
  traceback changes from "During handling of the above exception…" to "…was the
  direct cause of…"), and `from None` suppresses the original traceback outright.
  There is no behavior-preserving variant. Resolves the B904 half of **deferred
  entry 37**.
- **`RUF005` (8)** — `a + [b]` → `[*a, b]` differs when `a` is not a list. Seven
  sites have a locally provable list/tuple operand; `_properties.py:608` does not
  and is freeze-locked (§5).
- **`SIM102` (3) / `SIM103` (3) / `SIM114` (2)** — SIM102 and SIM114 collapse
  branches whose short-circuit order is unchanged (`if A: if B: S` ≡ `if A and
  B: S` when the outer body is exactly the inner `if`; `if A: X elif B: X` ≡ `if A
  or B: X`). SIM103 changes the *returned object* from the `True`/`False`
  singleton to the condition's raw value, so it is fixed only where the condition
  is provably a `str` (`bool(...)`) and freeze-locked where the condition is a call
  that is not proven to return a `bool`.
- **`UP031` (14)** — 13 sites take arguments that are provably `str`, or an
  explicit tuple literal matching the placeholder count, or `len(...)`; for all of
  those `'%s' % x` and `f'{x}'` agree, because `format(x, '')` is `str(x)`. The
  14th, `pdscache.py:321`'s `'127.0.0.1:%d' % port`, does not: `%d` truncates a
  float, `{port:d}` raises on one, and `{port}` prints it. Freeze-locked.
- **`UP024` (20)** — genuinely safe, and worth saying why rather than lumping in:
  `IOError` and `EnvironmentError` are not merely spelled differently in Python 3,
  they **are** `OSError` (`IOError is OSError`), so even the class name printed in
  a traceback is `OSError` today. All 20 fixed.
- **`N806` (2)** — both are locals inside one classmethod
  (`pdsfile.py:1414`, `:1442`); neither is part of any signature.
- **`UP004` (4)** — includes `class PdsFile(…, object)`. The Phase-5 addendum
  `plans/2026-07-27-addendum-phase5-mixin-base-order.md` already rules that trailing
  `object` is not a mixin, is not required, gives an identical MRO, and is left for
  PR-23; it also names the one line to drop with it,
  `test_the_class_statement_stays_in_pdsfile_pdsfile`'s
  `assert PdsFile.__bases__[-1] is object`, "which stops being meaningful once
  `object` is gone". Verification is a measurement, not an assumption:
  `PdsFile.__mro__` is dumped before and after and the two lists compared, and the
  mixin harness (`tests/api/test_mixin_collisions.py`, which discovers mixins by
  filtering `object` out of `__bases__`) is re-run.

## 7. Two `F401`s that are fixed rather than frozen

`pdsfile.pdscache.sys` and `pdsfile.pdsviewable.pdslogger` are **frozen manifest
members**, so deleting either import is a manifest break. They are not
freeze-locked all the same: `pdsfile.py` already establishes this repo's explicit
re-export form for exactly this situation — `import bisect as bisect`, with a
comment saying "the redundant `as` alias is the explicit re-export form" — and
ruff honours it (`pdsfile.py` binds ten unused stdlib modules that way and reports
no `F401`). So both become `import sys as sys` / `import pdslogger as pdslogger`
with the same comment. The name stays bound, the manifest is unchanged, and the
violation is genuinely gone rather than suppressed.
