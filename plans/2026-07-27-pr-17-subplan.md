## 1. What moves

Fourteen methods, located by name (the parent plan's ":1259–1661" and
":5061–5359" windows have drifted — PR-15 and PR-16 both edited this file).

**`src/pdsfile/_shelves.py`, `class _ShelfMixin`** — `shelf_path_and_lskip`,
`shelf_path_and_key`, `_get_shelf`, `_close_shelf`, `close_all_shelves`,
`shelf_lookup`, `shelf_path_and_key_for_abspath`, `info_shelf_expected`
(a property), `shelf_exists_if_expected`.

**`src/pdsfile/_local_fs.py`, `class _LocalFsMixin`** — `_non_checksum_abspath`,
`os_path_exists`, `os_path_isdir`, `os_listdir`, `glob_glob`, plus the module
constant `PATH_EXISTS_CACHE_SIZE` (public → re-exported by `pdsfile.py`).

**Stays on `PdsFile`:** every class attribute in the shelf-support block —
`SHELF_CACHE`, `SHELF_ACCESS`, `SHELF_CACHE_SIZE`, `SHELF_CACHE_SLOP`,
`SHELF_ACCESS_COUNT`, `SHELF_NULL_KEY_VALUES`. The plan names three of the six;
all six are class attributes and the preamble keeps class attributes on
`PdsFile`, so all six stay. `SHELF_PATH_INFO` is defined on the `Pds3File` /
`Pds4File` subclasses and is not touched.

The two mixins share no names, and `_local_fs` reaches `_shelves` only through
`cls.` (`cls.shelf_path_and_key_for_abspath`, `cls._get_shelf`) — a runtime MRO
lookup, not an import. That is the coupling the parent plan means by "it calls
into `_shelves.py`, which is why it moves in the same PR": neither module
imports the other, but `os_path_exists` / `os_path_isdir` / `os_listdir` /
`glob_glob` are broken unless both mixins are bases of the same class.

## 2. The sweep, done mechanically — and in both directions

**Direction 1 — what must move with the code.** Same two-pass method as PR-16:
CPython's `symtable` for the module-global names each moved method's *body*
references, plus an AST pass over each definition's *decorator expressions and
argument defaults*, which are evaluated in module scope and which `symtable`
does not attribute to the method. The second pass is not optional here:
`PATH_EXISTS_CACHE_SIZE` appears **only** inside
`@functools.lru_cache(maxsize=PATH_EXISTS_CACHE_SIZE)`, exactly the shape that
caught PR-16 out with `_GLOB_CACHE_SIZE`. A body-only sweep reports it
unreferenced and `_local_fs.py` raises `NameError` at import.

The sweep's full output, including its "nothing else" lines, goes in the
validation record.

**Direction 2 — who *patches* what this PR moves** (deferred entry 29, opened by
PR-16's round-1 Major and owned by "PR-17 onward"). The free-variable sweep
cannot see a test that patches a name on a module the code no longer resolves
through; such a test keeps passing while testing nothing, and §6.2's outcome-set
diff is structurally blind to it. `_local_fs` is the worst case in the phase,
because it is the `os.path.exists` / `os.listdir` / `glob.glob` seam that tests
patch. Required steps:

1. grep all of `tests/` and `scripts/` for `monkeypatch.setattr`,
   `monkeypatch.setitem`, `mock.patch`, `patch(`, `patch.object`, `setattr(`,
   and direct module-attribute assignment;
2. enumerate every site whose target names `pdsfile.pdsfile` or any symbol this
   PR moves, and classify each as still-reaching or broken;
3. for every such site, **prove the test still goes red when the patched
   behavior is wrong** — force the patched call to return a wrong value and
   confirm the failure. A test that passes both ways is worse than no test;
4. cover entry 29's extension: *rebinding* of re-exported module data
   (`PATH_EXISTS_CACHE_SIZE` here) as well as of modules.

Where a site needs repointing, use PR-16's fix shape — patch the function's own
`__globals__` — which follows the function through later moves.

## 4. Mixin mechanics — the pattern this PR sets

Fixed by the Phase-5 preamble, not by this executor:

- the `class PdsFile` statement **stays in `src/pdsfile/pdsfile.py`** (pickled
  instances and `PdsFile.__module__` depend on it; memcached pickles are live);
- the mixins define **no `__init__` and no new state** — methods, classmethods
  and properties only, referencing existing instance/class attributes;
- **no module-level `from pdsfile.pdsfile import PdsFile`** in a mixin module.
  None of the fourteen methods needs the class *object*, so no function-local
  deferred import is needed either — the sweep's "module-level CLASSES
  referenced: none" line is what says so;
- new names get a leading underscore: `_shelves`, `_local_fs`, `_ShelfMixin`,
  `_LocalFsMixin`, `_eval_null_key_record` are all freeze-invisible.

**Base order — decided here, for every later Phase-5 PR: alphabetical by mixin
class name, with `object` last.**

```python
class PdsFile(_LocalFsMixin, _ShelfMixin, object):
```

Why alphabetical rather than dependency order or append-on-arrival:

1. **MRO order is behaviorally inert here, and is kept that way on purpose.** The
   mixins share no attribute name and none shadows a `PdsFile` member — which is
   precisely what `tests/api/test_mixin_collisions.py` asserts. So the ordering
   rule cannot be chosen for semantics; it should be chosen for reviewability.
2. **Append-on-arrival encodes PR chronology** into the class statement. A reader
   cannot derive it, a reviewer cannot check it, and by PR-22 the list would be
   eight entries whose order means "the sequence six executors happened to run
   in".
3. **Alphabetical gives every future mixin exactly one legal position**, derivable
   without knowing anything about PR order, and it is machine-checkable — so the
   convention is enforced by the test rather than by each executor having read
   this paragraph.
4. **Dependency order would be a lie.** `_LocalFsMixin` calls into `_ShelfMixin`,
   but through `cls.`, so no ordering of bases expresses or affects it.
5. `object` stays last, where it is today, so `PdsFile.__bases__[-1] is object`
   is unchanged.

**`tests/api/test_mixin_collisions.py`** (its own file — §6.4 forbids putting new
API-adjacent assertions in `test_api_freeze.py`). It **discovers** the mixins
from `PdsFile.__bases__` rather than hard-coding today's two, so PR-18–22 get the
checks for free, and it asserts:

- the discovered set is non-empty and each member lives in a `pdsfile._*` module
  (so the test cannot pass vacuously — the PR-14 lesson);
- no attribute name is defined by more than one mixin (the set-intersection check
  the preamble asks for);
- no mixin defines a name that `PdsFile`'s own body also defines (which would
  make the mixin's copy silently dead);
- no mixin defines `__init__`, `__new__`, `__slots__`, or any non-callable class
  attribute — the preamble's "no `__init__` and no new state" as an assertion;
- the bases are in the §4 order, and `PdsFile.__module__` is still
  `pdsfile.pdsfile`.

`tests/api/conftest.py` marks everything collected from that directory
`holdings_free` (PR-14), so the new file inherits it and runs in the hosted
no-holdings job. That is verified by running it with no holdings env vars, not
assumed.

## 5. The `eval()`, isolated with a documented contract

Parent plan: "The `eval()` of the `.py` sidecar line is kept (behavior) but
isolated in one named function with a documented contract." Today it is three
lines inside `shelf_lookup`:

```python
parts = rec.partition(':')
values = eval(parts[2].strip()[:-1])
```

They become a call to a module-level private function in `_shelves.py`,
`_eval_null_key_record(rec)`, whose docstring is the deliverable. What the
contract must state, as **description of what happens today**, not as new
validation (ground rule: behavior-preserving):

- what the input is (the *second* line of an info-shelf `*_info.py` sidecar, as
  returned by `readline()`, so it still carries its newline);
- the shape expected (`"": (nbytes, count, modtime, checksum, (width, height)),`);
- exactly what the parse does — partition on the **first** `':'`, `strip()`, drop
  the final character (the trailing comma), `eval` the rest;
- what happens on malformed input **today**: no colon → `eval('')` →
  `SyntaxError`; an incomplete expression → `SyntaxError`; a line not ending in
  the trailing comma → its last character is dropped regardless, which can turn a
  valid expression into a different valid expression; a bare name in the
  expression → resolved against this module's globals, then builtins, else
  `NameError`;
- that `eval` executes whatever the file contains, so the trust boundary is the
  holdings tree, whose `_info.py` sidecars are written by this package's own
  maintenance tools.

One consequence must be measured rather than waved past: the `eval` moves from
`pdsfile.pdsfile`'s module namespace to `pdsfile._shelves`'s. For any record that
is a tuple of literals, evaluation touches no name at all and the namespaces are
indistinguishable. The check is therefore: parse the second line of every
`*_info.py` sidecar reachable under `PDS3_HOLDINGS_DIR` / `PDS4_HOLDINGS_DIR`
with `ast` and confirm **none contains a `Name` node** — i.e. no real record can
observe which module's globals were in scope. Recorded with the file count.

No validation is added, no exception type changes, and `eval` is not replaced by
`ast.literal_eval` — that would be a behavior change (it would reject records
`eval` accepts) and ground rule 9 / §6.4 forbid it.

## 6. Ruff ratchet

`per-file-ignores` may only shrink. Same per-code procedure PR-16 recorded, with
its two extra flags (`--isolated` also drops `line-length = 100`, so it must be
restored or E501 appears at 88 columns):

```
ruff check --no-cache --isolated --select <code> \
           --line-length 100 --target-version py310 <file>
```

1. For every code in `pdsfile.py`'s entry, run the above against `pdsfile.py`,
   `_shelves.py` and `_local_fs.py` after the move.
2. Each new module gets an entry listing **exactly** the codes its moved lines
   still trigger. Every such code must already be in `pdsfile.py`'s entry — the
   entries are a **split**, not a new suppression. **A code that is not already
   there is a §6.4 hard stop.**
3. Any code `pdsfile.py` no longer triggers is **removed** from its entry.
4. Net effect recorded as a before/after per-code count.

Moved bodies are not restyled to shed an inherited violation — that is a content
edit inside a move PR, and it belongs to PR-23.

## 7. Keeping `pdsfile.pdsfile.X` resolving

The preamble's rule is "`pdsfile.py` keeps re-exporting every name it exports
today", with no public/private qualifier (settled in PR-16 §8.1). The measured
invariant is therefore `sorted(vars(pdsfile.pdsfile))`: **no name lost.**

Six names become unreferenced inside `pdsfile.py` after the move and must stay
bound anyway — `bisect`, `fnmatch`, `functools` and `pickle` are frozen members
of the module's public surface (`tests/api/api_manifest.json`); `_clean_glob` is
private but carried for the zero-names-lost invariant; `PATH_EXISTS_CACHE_SIZE`
is frozen and now comes from `_local_fs`. `pdsfile.py`'s ratchet entry contains
no `F401` and the ratchet header forbids both growing it and adding an inline
`noqa`, so all of them use the PEP-484 redundant-alias form (`import pickle as
pickle`, `PATH_EXISTS_CACHE_SIZE as PATH_EXISTS_CACHE_SIZE`) that PR-16
established. Verified by rewriting them in plain form and counting the resulting
F401s, not by assumption.

Two names are **added** to `pdsfile.py`'s namespace: `_ShelfMixin` and
`_LocalFsMixin`, which the `class PdsFile` statement needs. Both are underscore
names, so the manifest does not see them; the invariant is "none lost", and the
two gains are named and expected.

was written first stays readable as what it was. Four statements above are no

4. **§4's `tests/api/test_mixin_collisions.py` bullet list grew two entries.**

   nothing at all. All six were injected into each mixin module and measured.

5. **Point 4 above is superseded: the back-import check was removed again before
