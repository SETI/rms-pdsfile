## 2. The rule that decides what `_common.py` may hold

A difference between the two halves of a pair belongs in `ToolSpec` only if it
is **data**: a class, a string, a log level, a tuple of handler factories, or a
callable that computes a path or a list of targets. **A difference in control
flow is not data.** If sharing a function would need a boolean flag whose only
job is to re-create one side's quirk, the function is not shared — it stays in
its tool module and the divergence is recorded.

`_common.py` earning its place means removing real duplication, not
accumulating flags.

## 4. Verification steps

1. **The archives pair's CLI is byte-identical.** `--help` captured from both
   trees under a fixed `COLUMNS`, and — because argparse re-wraps help text and
   would hide a whitespace change — a dump of every `ArgumentParser.__init__`
   and `.add_argument` call with its arguments, keywords and order, from both
   trees. Both must diff empty.
2. **The Phase-6 per-tool gate.** Run each migrated tool over a real volume and
   a real bundle set copied out of the holdings, at the base and at the head,
   over the same task sequence; diff stdout and every log file written,
   normalized for clock, elapsed time, disk path and log time tag.
3. **The full-data suite**, both modes, on a baseline worktree at `ab1fa3b` and
   on the branch, per-test id sets diffed. The only permitted movement is the
   ids the deferred-81 tests add.
4. **Non-vacuity.** `coverage.CoverageData.measured_files()` read for absolute
   paths, to prove each run imported its own worktree and not the main tree's
   editable install. `_common.py` is the decisive marker: a new file, absent
   from the baseline.
5. **The deferred-81 test, built so it cannot pass vacuously.** Write it for a
   **pds4** tool first and confirm it passes against unmodified code; write the
   identical test for the **pds3** twin and confirm it **fails**; apply the fix
   and confirm both pass. Then revert the fix in a scratch copy and confirm
   every pds3 test fails again.
6. The remaining §2 gates: API-freeze test, `ruff check`, the indentation pass,
   clean install, and the hosted no-holdings run.
7. The §6.6 adversarial review loop to convergence.

## 5. Known traps

- The only usable interpreter is the main tree's venv, whose editable install
  puts `/seti/all_repos/rms-pdsfile/src` on `sys.path`. Every measurement must
  set `PYTHONPATH` **and** prove which files were imported; assuming
  `PYTHONPATH` won is how a whole comparison goes vacuous.
- `logger.info` and `logger.normal` are **not** interchangeable: they render
  different level names, produce different closing summaries, and an
  `{'info': N}` limits entry does not constrain `normal`. The level must be
  carried as data, not converged.
- `_common.py` is a new file, so any `per-file-ignores` entry for it is a new
  key — a widen, which §6.4 forbids. It must be written clean.
- `re_validate.py` is frozen and calls `pdsarchives.validate(pdsdir, limits=…)`.
  That signature may not change.
